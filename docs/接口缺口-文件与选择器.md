# 接口缺口：文件上传与业务对象选择

> 日期：2026-11-11 ｜ 适用范围：mentor-web 管理端 / 导师端
>
> 本轮要求：
>
> 1. 除系统菜单外，不再让用户手工填写业务 ID，改为下拉选择；
> 2. 所有涉及佐证文件、归档等需要文件证明的功能都应支持上传；
> 3. 当前接口无法支持的，记录在本文件。

---

## 处理结果

后端已补齐 4 项：

| # | 缺口 | 后端接口 / 行为 |
| --- | --- | --- |
| 1 | 归档附件上传 / 预览 / 下载 | `ArchiveItem.fileIds` / `files`；`POST/PATCH /archives` 收 `fileIds`；`GET /archives/:id/files/:fileId/preview\|download`；归档目标类型增加 `StudentAchievement` |
| 2 | 考核申诉佐证 | `AssessmentAppeal.fileIds` / `files`；`POST /assessments/:id/appeals` 收 `fileIds`；申诉响应返回 `files`；`GET /assessments/:id/appeals/:appealId/files/:fileId/preview\|download` |
| 3 | 学生成果佐证上传权限 | seed 给 `college_admin` / `sc_admin` 增加 `file:create` |
| 4 | 学生下拉数据源 | `GET /student-achievements/students?keyword=&deptId=&page=&pageSize=` |
| 5 | 归档核心 / 非核心切换 | `PATCH /archives/:id/core` `{ "core": 0/1 }`；核心清空保留期，非核心重新计算保留期 |
| 6 | 学生成果佐证自动归档 | 关联导师时自动归档的 `fileIds` 带上 `proofFileId` |

前端已完成对应适配。

## 一、已适配

| 功能 | 处理方式 |
| --- | --- |
| 归档列表「导师」筛选 | 已生效导师下拉（`GET /mentors`），列表显示导师姓名 |
| 新建 / 修改归档「归属导师 / 归属学院」 | 导师下拉、部门树下拉 |
| 新建归档「归档对象」 | 按目标类型下拉：入驻申请、考核、导师成果（先选导师）、学生成果、其他 |
| 归档附件 | 新建 / 修改归档时可上传、移除附件；详情中可预览、下载 |
| 考核申诉佐证 | 导师提交申诉时可上传、移除附件；申诉列表可预览、下载 |
| 学生成果「学生 / 导师」筛选 | 学生下拉走 `GET /student-achievements/students`（姓名 / 学号搜索，按数据范围过滤），导师下拉走 `GET /mentors` |
| 登记学生成果「学生」 | 学生目录下拉；目录为空时（学生同步未开启）回退到「有预约 + 有成果」的学生 |
| 登记学生成果「佐证文件」 | 文件上传，写入 `proofFileId`；列表支持预览 / 下载 |
| 导师成果「佐证文件」 | 上传、预览、下载；不再显示只读文件 ID，改为显示文件名 / 已上传 |
| 业务 ID 展示 | 能解析的 ID 已换成姓名 / 名称；无法解析的按「编号」展示 |

> `POST /files` 需要 `file:create`。前端仍保留权限判断：账号没有该权限时，学生成果佐证区域显示提示而不是直接报 403；当前 seed 已给 `college_admin` / `sc_admin` 授权。

## 二、仍待后端支持

### 1. 归档目标「指导记录」检索

现状：

- 手工归档目标类型 `GuidanceRecord` 需要指导记录 ID；
- 没有管理员全局检索指导记录的接口（`GET /mentors/records` 只返回导师本人记录，`GET /stats/me/records` 只返回本人）。

处理：前端手工归档暂不提供 `GuidanceRecord` 目标类型，避免要求用户手填记录 ID。

建议后端补充：

- `GET /guidance-records?mentorId=&from=&to=&page=&pageSize=`（按数据范围过滤），或在预约列表中返回关联指导记录 ID。

### 2. 归档目标「双创成果」全局检索（可选）

导师成果目前只能通过 `GET /mentors/:mentorId/achievements` 按导师查询；前端已采用「先选导师、再选成果」的方式。若需要跨导师按成果名称搜索，建议增加：

- `GET /achievements?keyword=&mentorId=&page=&pageSize=`。

### 3. 业务 ID 的关联信息缺口

| 位置 | 当前字段 | 缺口 |
| --- | --- | --- |
| 入驻审核列表 / 详情「申请人」 | `applicantId` | 响应没有 `applicantName`；只能显示「申请人编号」 |
| 归档详情「导师」 | `mentorId` | 响应没有 `mentorName` 快照；已用已生效导师映射，导师已移出导师库时只能回退「导师编号」 |
| 归档详情「关联对象」 | `targetType` + `targetId` | 没有目标对象名称快照；只能显示「目标类型 / 目标编号」 |
| 文件管理「上传人」 | `uploaderId` | 响应没有 `uploaderName`；只能显示「上传人编号」 |
| 操作日志「目标对象」 | `targetType` + `targetId` | 没有目标对象名称；只能显示「类型 / 编号」 |
| 预约详情「命中时段」 | `slotId` | 没有时段详情（星期 / 起止时间）；只能显示「命中时段编号」 |

建议后端补充名称快照：

- `GET /mentor-applications`：`applicantName`；
- `GET /archives` / `GET /archives/:id`：`mentorName`、`targetName`；
- `GET /files`：`uploaderName`；
- `GET /system/oplogs`：`targetName`（可选）；
- 预约详情：`slot` 摘要（weekday + startTime + endTime）。

## 三、当前交互约定

- 系统菜单（用户、角色、权限、部门、字典、操作日志、文件管理、系统配置、定时同步）仍允许维护系统级标识，因为它们是系统管理对象，不属于业务填报。
- 业务表单中的业务对象统一使用下拉框；无法提供下拉数据源的项已在上面列出。
- 文件上传统一限制：图片 / PDF，单文件 ≤ 10 MB，单次 ≤ 10 个；选择文件时即时校验并显示已选数量。
